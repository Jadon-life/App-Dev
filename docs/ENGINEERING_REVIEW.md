# CrysLearn engineering review

Implementation and verification in the existing `App-Dev` checkout. Production data and the existing Vercel deployment were not changed. See [development and rollout instructions](DEVELOPMENT.md).

## 1. Application assessment

CrysLearn prepares Nigerian students for UTME and WAEC. The web app contains an exam catalog, question practice, timed mocks, saved results, payments and a weekly planner. Expo SDK 51 provides a mobile companion sharing Supabase accounts and results. Next.js, TypeScript, Tailwind, React Query, Supabase and Paystack remain the architecture.

The major weaknesses were inconsistent browser/server sessions, disabled private-route protection, client-controlled exam scores, unsafe parent linking, insufficient payment validation, fabricated dashboard activity, inert mobile controls, and advertised functionality without an implementation. An animation-only entrance and scattered theme providers made basic navigation and theme behavior fragile.

## 3. UI/UX transformation

- A restrained ink, paper and teal identity replaces repeated gradients/glows. Local Geist typography, editorial display headings and shared surface/input/button styles establish hierarchy across screens.
- The root route now explains the product and offers a direct start. The original interactive book remains an optional preview, with a text alternative for reduced-motion or unsupported WebGL.
- Responsive navigation exposes every study section with labels, active state, a skip link and mobile scrolling contained within the navigation. The nonfunctional notification icon was removed.
- Login, onboarding, exam selection, practice, timed mocks, results, checkout, dashboard, planner, settings and availability screens use intentional layouts and meaningful error/empty/loading feedback.
- Theme choice persists without storage exceptions, works across tabs and avoids an initial wrong-theme flash. Web light/dark styles share the same semantic palette; native retains a consistent dark theme.
- Form labels, radio/checkbox semantics, minimum touch areas, visible focus, keyboard dialogs and reduced-motion behavior were addressed. Automated browser checks include desktop and mobile layouts and document overflow.

## 4. Performance and maintainability

- No WebGL canvas is constructed on initial landing. The book/Three.js chunk is loaded only on request; the browser test asserts zero initial canvases.
- Removed unused React Three Fiber/Drei, chart and form dependencies. Existing raw Three.js functionality is retained.
- WebGL components release their GPU resources/canvases, stop hidden-tab loops and respect reduced motion; magnetic-button tweens are cleaned up.
- Shared auth state removes duplicated listeners and clears cached private data on account changes. Practice queries paginate and cancel obsolete requests; available years use a bounded server query rather than downloading the whole bank.
- Fonts are served locally; the remote Google Fonts stylesheet import was removed.
- Mobile directly imports its one used icon family. Final iOS JavaScript export is **2.92 MB with 11 assets**; the intermediate all-family export was 3.17 MB with 29 assets. This is a bundle measurement, not a native startup benchmark.
- Regression helpers isolate validation, score calculation, scheduling, storage and fulfillment logic. No new application framework or state manager was introduced.

## 6. Remaining issues and limitations

- **Live schema rollout is required.** Migrations 00008 and 00009 are reviewed/tested files, not changes already applied to your Supabase project. Coordinate the new schema and web release; old browser clients use writes that migration 00009 revokes. The new API reports a setup error when required columns are absent.
- Parent sharing needs a real student-consent model. AI needs a backend/provider integration. Offline question packs need a native download/storage workflow. These were unfinished beforehand and are now represented honestly instead of generating fake activity or claiming unavailable access.
- Live email confirmation, Google provider configuration, Paystack test-mode checkout and delivered webhooks still need staging validation with configured services and a test account. Unit/fixture success is not evidence those external integrations work in production.
- Historical attempts retain their stored scores. They cannot reconstruct question composition that the former application never saved.
- Native compilation, device layouts, SecureStore on a device, OS lifecycle and real native authentication have not been validated. The aligned Expo 51 cohort and its 15 native dependencies pass the SDK compatibility matrix, and its Hermes export passes. This is still an older SDK and device testing is required before a native release; branded app-store assets are also still needed.
- Dependency audits still report advisories. The web production audit has **four high findings** in one linked glob-tool chain (`braces`, `micromatch`, `fast-glob`, `globby`), with no critical/moderate findings in that audit. These are build/tool dependencies, and the affected deep-pattern parser does not have a compatible patched upstream release at the time of this run. They have not been suppressed. The updated production-workspace audit reports **71 affected-package findings: 0 critical, 42 high, 28 moderate and 1 low**. The four prior critical findings were removed by aligning the mobile SDK/server cohort and patching the archive dependency. High/moderate findings remain in the legacy native/build tool chain; this is not a clean security audit, and wider SDK modernization/device validation remain release considerations.
- This is a learning product, not a proctored exam system: authenticated practice deliberately provides answer explanations. Server grading protects persisted scores; it does not prevent someone consulting practice material.

## 7. Final status

The application has implemented security, reliability and visual improvements with repeatable unit, browser and database checks. Changes are prepared on the review branch `codex/cryslearn-refinement`; production remains unchanged until the tested schema and release are promoted together. It is **not yet an unconditional production-ready release**: complete the coordinated database rollout, staging integrations, dependency follow-up and native-device validation first.
